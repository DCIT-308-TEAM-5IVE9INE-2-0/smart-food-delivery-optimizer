## Purpose

The first meeting introduced the joint semester project, reviewed the brief, recorded initial attendance, discussed possible Ghanaian problem contexts, and agreed on how the group would collaborate.

## Agenda

### 1. Opening And Attendance

- Welcome group members.
- Record members present and absent.
- Confirm the group name and communication channel.
- Identify members with technical, documentation, database, testing or presentation strengths.

### 2. Project Brief Review

- Review the lecturer's project expectations.
- Confirm that the project must include data structures, algorithms, database storage, tests, performance graphs, documentation and oral defence.
- Note that each member must be able to explain one data structure and one algorithm or project area.

### 3. Local Problem Context Discussion

Possible Ghanaian contexts discussed:

- Food delivery or courier dispatch.
- Campus service operations.
- Transport or route planning.
- Resource allocation and scheduling.

Key evaluation points:

- The context must be local and realistic.
- The dataset must include Ghanaian places, service requests, resources and constraints.
- The problem should naturally support queues, graphs, searching, sorting, greedy methods and dynamic programming.

### 4. Initial Technical Direction

The group agreed that the solution should be simple enough to complete but strong enough to satisfy the project brief.

Initial technical preferences:

- Java as the main programming language.
- A console application as the user interface.
- A database-backed system instead of only CSV processing.
- Custom implementations for assessed data structures.
- Unit tests and trace tables for correctness evidence.

### 5. Initial Roles And Responsibilities

The group identified the need for working areas:

- Technical development and integration.
- Database and dataset.
- Testing, correctness and performance.
- Research, documentation and report.
- Presentation, oral defence and media.

Final member alignment was scheduled for the next meeting.

### 6. Collaboration Plan

- Use WhatsApp for quick communication.
- Use GitHub for source-code collaboration.
- Keep project documents inside `/docs`.
- Keep final submission materials inside `/submission`.
- Record major decisions in meeting notes.
